# RAG 방식 비교 벤치마크 계획서

## 비교 대상 3가지 방식

| 방식 | 파이프라인 | 설명 |
|------|-----------|------|
| 방식1 | 키워드 → LLM | RAG 없이 LLM에 질문만 전달. 일반 지식 기반 답변 |
| 방식2 | 키워드 → RAG → LLM | bge-m3 임베딩 + Hybrid Search로 관련 chunk 검색 후 LLM에 context로 전달 |
| 방식3 | 키워드 → RAG → MergePRAG → LLM | 검색된 chunk를 MergePRAG로 정교하게 통합한 뒤 LLM에 전달 |

---

## 1. 정량적 지표

### 1-1. 답변 품질 (정확성)

| 지표 | 측정 방법 | 비고 |
|------|-----------|------|
| Faithfulness | 답변이 실제 강의 내용에 근거하는가 (환각 비율) | 방식1은 강의 내용 참조 불가 |
| Relevance | 질문에 대한 답변의 관련성 (1~5 Likert) | 수동 평가 |
| Completeness | 필요한 정보를 빠짐없이 포함하는가 | Gold Answer 대비 비교 |
| Factual Accuracy | 정답 기준 대비 사실 정확도 (%) | 자동 + 수동 평가 |

### 1-2. 속도

| 지표 | 설명 |
|------|------|
| End-to-End Latency | 질문 입력 → 답변 완료까지 총 시간 (ms) |
| Retrieval Latency | 검색만 걸리는 시간 (방식1은 0) |
| Generation Latency | LLM 생성 시간 |
| TTFT (Time to First Token) | 첫 토큰 나올 때까지 시간 |

### 1-3. 검색 품질 (방식2, 3만 해당)

| 지표 | 설명 |
|------|------|
| Hit Rate | top-k 안에 정답 chunk가 포함된 비율 |
| MRR (Mean Reciprocal Rank) | 정답 chunk가 몇 번째에 위치하는가 |
| Context Precision | 가져온 chunk 중 실제 관련 있는 비율 |

## 2. 정성적 비교 (발표용 시각 자료)

### 2-1. 답변 비교 표

동일 질문에 대한 3가지 방식의 답변을 나란히 배치.

```
질문: "OSI 7계층에서 TCP는 몇 계층인가?"

┌─────────────────────────────────────────────────┐
│ 방식1 (LLM only)                                 │
│ "TCP는 4계층(전송 계층)에 해당합니다."              │
│ → 맞지만 강의 맥락 없음                           │
├─────────────────────────────────────────────────┤
│ 방식2 (RAG + LLM)                                │
│ "강의에서 다룬 것처럼 TCP는 전송 계층입니다.        │
│  UDP와 달리 신뢰성을 중시합니다."                   │
│ [출처: 컴퓨터공학개론 > 3주차 > 3:00~6:00]         │
│ → 강의 내용 기반이지만 단순 참조                    │
├─────────────────────────────────────────────────┤
│ 방식3 (MergePRAG + LLM)                          │
│ "3주차 강의에서 OSI vs TCP/IP 모델을 비교했는데,    │
│  TCP는 전송 계층으로 신뢰성 있는 전달을 담당합니다.  │
│  같은 강의에서 UDP와의 차이도 설명했습니다."         │
│ [출처: 컴퓨터공학개론 > 3주차 > 2:00~6:00]         │
│ → 여러 chunk를 자연스럽게 통합                      │
└─────────────────────────────────────────────────┘
```

### 2-2. 환각(Hallucination) 비교

방식1이 환각이 가장 많고, 방식3이 가장 적다는 것을 보여줌.

```
질문: "교수님이 설명한 필립스 곡선의 한계는?"

방식1: "필립스 곡선은 스태그플레이션을 설명하지 못합니다..."
       → 일반 지식, 교수님이 실제로 한 말이 아닐 수 있음 (환각 위험)

방식3: "3주차 강의에서 '장기적으로는 단순한 역관계로 보기 어렵다'고
        설명하셨습니다."
       → 실제 전사 데이터 기반 (환각 없음)
```

## 4. 평가 방법

### 4-1. 자동 평가 (RAGAS 프레임워크)

```python
# pip install ragas
from ragas.metrics import faithfulness, answer_relevancy, context_precision
from ragas import evaluate

# 각 방식별로 실행 후 결과를 모아서 평가
```

- `faithfulness`: 답변이 검색된 context에 근거하는가 (0~1)
- `answer_relevancy`: 답변이 질문에 관련 있는가 (0~1)
- `context_precision`: 검색된 context 중 관련 있는 비율 (0~1)

### 4-2. 수동 평가 (블라인드 테스트)

1. 30개 질문에 대해 3가지 방식의 답변을 생성
2. 답변을 A/B/C로 랜덤 라벨링 (어떤 방식인지 모르게)
3. 평가자 3~5명이 각 질문마다 "가장 좋은 답변" 선택
4. 선호도 비율 집계

### 4-3. 속도 측정

```python
import time

# 각 방식별 30개 질문 실행
for question in questions:
    start = time.time()
    # 방식 실행
    end = time.time()
    latency = end - start
```

## 5. 발표용 최종 비교 차트 (예상)

```
              │ 방식1        │ 방식2         │ 방식3
              │ LLM only     │ RAG + LLM     │ MergePRAG + LLM
──────────────┼─────────────┼──────────────┼───────────────
정확도         │ ~60%        │ ~78%          │ ~89%
환각률         │ ~35%        │ ~15%          │ ~5%
강의맥락 반영   │ 0%          │ ~70%          │ ~92%
출처 제공       │ X           │ O             │ O (더 정밀)
평균 응답시간   │ ~3.2s       │ ~4.1s         │ ~4.5s
사용자 선호도   │ ~20%        │ ~30%          │ ~50%
```

핵심 메시지: "속도는 약간 느려지지만, 정확도와 강의 맥락 반영이 압도적으로 향상됨"

## 6. 실행 순서

1. 방식1, 2 완성 및 동작 확인 (현재 완료)
2. 30개 질문셋 + Gold Answer 최종 확정
3. 방식1, 2로 30개 질문 실행 → 답변 + 속도 기록
4. MergePRAG 구현 (방식3)
5. 방식3으로 30개 질문 실행 → 답변 + 속도 기록
6. RAGAS 자동 평가 실행
7. 블라인드 수동 평가 실행
8. 결과 정리 및 발표 자료 제작

## 7. 기술 스택

- 임베딩 모델: BAAI/bge-m3 (1024차원)
- LLM: Qwen3.5-9B (4-bit 양자화)
- Vector DB: PostgreSQL + pgvector
- 검색: Hybrid Search (벡터 유사도 + 키워드 ILIKE)
- 프레임워크: llama_index, FastAPI
- 평가: RAGAS
- GPU: RTX 5070 Ti (16GB VRAM)
