================================================================
D. 어떻게 해야 하는지 (실행 우선순위)
================================================================

[Phase 1: API 계약 통일]
1) 백엔드 단일 계약 결정
   - 옵션 A: OpenAI 호환(v1/chat/completions) 유지
   - 옵션 B: /generate 계약으로 단순화
2) 현재 권장: OpenAI 호환 유지 (backend/main.py와 docs 방향 일치)
3) llm_server를 계속 쓸 경우, OpenAI 호환 엔드포인트 추가 필요.

[Phase 2: MergePRAG 산출물 표준화]
1) hypernetwork 출력(delta K/V 또는 delta W)을 LoRA A/B로 변환 규격 정의
2) PEFT 어댑터 디렉토리 생성기 구현
   - adapter_config.json
   - adapter_model.safetensors
3) 어댑터 버전/메타데이터(생성 시각, 데이터 출처, rank) 저장.

[Phase 3: vLLM Multi-LoRA 동적 연동]
1) vLLM 서버 실행 옵션 확정(LoRA 기능 포함)
2) 백엔드에 "어댑터 로드/언로드/상태조회" 오케스트레이터 추가
3) 요청별 adapter_id 라우팅(사용자/세션/강의 단위).

[Phase 4: 병합 안정성/압축]
1) orthogonal_merge 수식 단위 테스트 추가(직교성, rank 증가, 수치 안정성)
2) rank budget 초과 시 SVD 압축 파이프라인 추가
3) 압축 전/후 품질 회귀 테스트 구축.

[Phase 5: 운영 품질]
1) 절대 경로 제거 -> 환경변수/설정 파일화
2) 하드코딩 키 제거
3) E2E 테스트(샘플 질의로 adapter 반영 여부 검증) 추가.
